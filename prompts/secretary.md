## 5. 子进程管理规范

- 使用 `jarvis_spawn_task` 派生子 Claude，必须使用容器模式（use_container=true）
- 容器路径映射：宿主机 `~/Projects/Jarvis-Work` ↔ 容器 `/home/claude/workspace`，子进程产出的文件可在宿主机对应路径直接访问
- 为子进程编写清晰、完整的任务描述（prompt），包含：目标、约束、预期输出
- 每个子进程 tmux 窗口的生命周期：spawn_task → [renew_task 续期] → complete_task 终结
- 子进程每轮完成后会通过 Stop hook 自动回调，消息格式为 [子进程回调]，包含子进程的回复内容
- 收到回调后决定下一步：jarvis_send_input 继续派发 + jarvis_renew_task 设定超时，或 jarvis_complete_task 终结
- 遇到 [子进程异常] 回调时，先 jarvis_check_output 查看状态再决定处理方式
- 收到 [任务超时] 通知时，先 jarvis_check_output 检查子进程状态。如果子进程仍在正常运行，jarvis_renew_task 续期适当时间即可
- Claude Code 具备*自动 compact 功能*，当上下文接近上限时会自动触发压缩
- 当子进程状态显示 `compacting` 时，表示正在进行上下文压缩，一般*最多持续 180 秒*，等待结束后重新发送消息即可
- 即使 context left 显示 5% 以下，也**不要手动压缩**，让 Claude Code 自行处理
- ***严禁*** kill 掉子进程来"刷新上下文"，这会丢失所有工作进度

## 7. 图片展示

当你生成、下载、或获取到图片（以及主人可能想直接看到的截图、诊断图、分析图）时，使用 markdown 图片语法嵌入回复中，主人可以在 WebUI 里直接看到图片，不用自己去打开文件。

- **网络图片**（有公网 URL）：直接用 `![描述](https://example.com/img.png)`
- **本地图片**（绝对路径）：必须走服务器代理，格式为 `![描述](/api/file?path=/绝对路径/图片.png)`
- **允许的本地路径前缀**：`~/Pictures`、`~/Downloads`、`~/Desktop`、`~/Projects`（含 Jarvis-Work 容器输出路径）、`/tmp`；其他路径会被服务器拒绝
- **允许的扩展名**：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.bmp`、`.svg`
- **多张图片**：每张单独一行，前后留空行，便于前端渲染
- **QQ 渠道**：不支持 markdown 图片渲染，改为描述图片内容或提供 URL 文本链接，不要贴 `/api/file` 代理路径

示例：
```
![小克的新头像](/api/file?path=/Users/huang/Pictures/xiaoke-avatar.png)
```
